## 0. 我们的环境与已经确认的事实（供你对照）

**客户端**：`DNF70_v50.exe`（55,574,528 字节，与你交接包里的 `Native E274F3` 同一基线族——
我们在自己构建里，VA `0xE274F3` 正好是 op46 请求构建函数写稀有度字节的位置，与你说的完全一致）。
我们分析用的基线版本 sha256 前缀 `ccc7823c…`；你们交接包里的 initial/candidate 是
`af5276dd…` / `6f6cbcde…`（两个哈希都不在我们的构建里，但地址语义能对上）。

**服务端**：与你们同源的 C# 离线服务端（`Batch-Service` 系列），拾取事务 = `op46 → 校验 → 背包事务 →
op39 + ack46`，品级表来自 CN70 PVF 的 `[rarity]`（我们建了 40447 行的 `item-rarity` 目录）。

**已确认的服务端侧**（均对实机抓包验证过）：

- `op46` 请求明文 16 字节：`slot(u16) @0`、`byte2 = 0`、**`byte3 = 地面物品资料稀有度`**、
  坐标在 4/6/10/12；服务端校验 `byte3` 与地面物品一致后入库（只对品级 ≥2 强制，0/1 只记日志）。
- 手动拾取成功的样本全部是品级 0/1（`FRAME opcode=46 bytes=29` 前后配对）；品级 ≥2 的怪物掉落，
  客户端**一帧请求都不发**。
- 我们按你交接包提示，在本机构建里找到 `0x93D45D: cmp dword ptr [物品对象+0xDC], 2 / jge → 弹串 0x874 放弃`，
  把立即数 2 改成 6（品级 0..5 全放行）后：**X 键拾取品级 ≥2 仍然不发 op46**；而且栈扫描显示该校验器
  在整局从未出现在任何线程栈上——它似乎不在 X 键路径上（更像鼠标点击路径）。品级 1 的丢弃物按 X
  能正常发出 op46 并被服务端入库（已验证）。
- 副本内丢弃：`op50` 请求明文 16 字节，实测布局
  `{X u16, Y u16, list u8=0, slot u16, qty u32, 确认标志 u8=1, 0,0,0,0}`（两个实机样本：装备 slot 25、
  材料 slot 136）。我们服务端按这个布局接受后，**处理成功却没有"落地"**：客户端收到我们发的
  落地通知（`0x28`/op40，type=0）后开始以 ~500 条/秒 发送 `OVERFLOW_INFO`（op232 正文解密为
  `{opcode 0x0028, 0×14}`），5~22 秒后挂死；两种候选行布局（下表）都触发。
- 普通击杀的死亡通知（`op38`/type=0）我们是按 27 字节/行发送的，客户端解析、显示、拾取全部正常：

  ```
  op38 每行 27B（实测可用）：slot u16, itemId u32, 数量 u32, 0 u16, 0 u8, 0 u16, 0 u32,
                               0×6, mapIndex u16
  ```

**已失败的两版 op40 落地行**（都会被客户端判为溢出）：

- A 版（红警 TW 原版顺序，31B）：`uid u16, X u16, Y u16, slot u16, itemId u32, attr u8,
  count u32, 耐久 u16, fieldd u32, ampType u8, ampValue u16, Inven_Item 4B, 标志 u8`
- B 版（死亡行形状，34B）：`uid u16, X u16, Y u16` + 上述 27B 死亡行原样 + `标志 u8`

我们服务端按 36 字节另一版（`u16 1, X, Y, slot, itemId, 数量@13, …`）发送时客户端**不溢出也不显示**，
只是静默忽略。

**已排除的静态路径**（不要再让你花时间）：静态分发表（文件偏移 `0x390C04`，索引=opcode）找不到引用，
包对象工厂（如 op40 的 `0x78F796 → init 0x781660 → [obj]=0x1455E0C`）的虚表在文件里全零、运行时才填；
描述子记录第三字段指向的地址并不是 op40 消费器（op185 对照指向的也不等于已知的 `0x894D20`）。

## 6. 我们这边的取舍说明（避免你们误会我们在乱试）

- 我们曾把副本内丢弃先改成"原地销毁"（物品直接消失、不发落地包），因为落地包的两个候选布局都会
  让客户端 `OVERFLOW_INFO` 风暴后挂死。玩家反馈"旧版本丢弃明明正常"，我们已**整体回滚**到
  FG395 之前的状态：严格 op50 解析（实机请求一律拒绝、无回包）、客户端品级闸门字节恢复 02、
  服务端代收关闭。
- 也就是说：现在我们这边"丢弃"能用（客户端本地预测出脚下物品）、"白装能捡"，
  但**捡自己丢出去的物品会挂死本局手捡**（服务端不认识那个本地槽）、品级 ≥2 仍然捡不起来。
  你们的经验正好补上这两块。
- 我们服务端新增了 GM 探针（可向副本内注入任意 `op40` 字节体、以及几种候选布局），
  只要你们给出真实布局，我们可以在不重启客户端的情况下在线验证并固化，不需要玩家再受苦。
