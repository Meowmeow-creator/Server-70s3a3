# FIX 2026-10-29：被俘的冒险家（救出/破坏物件类任务）不计数 —— FG383 物件破坏目标合成记账

## 症状

根特外围主线第 3 环「被俘的冒险家」（4203，"破坏地下城中的囚牢，救出7名冒险家"）：玩家在副本里救出冒险家后，任务计数不动，永远交不了。同类"破坏 XX"任务（破坏通讯器/清理路障/破坏虫茧/油桶的隐患等）同一缺口。

## 根因（全链取证）

1. **判定形态**：4203 是 `[hunt enemy]` 行 `{80, -1, 8824, 3, 7}`＝副本 80、任意难度、目标 **8824**、enemyType **3**、数量 7。enemyType=3 的语义是"破坏 `[passive object]` 物件"而非杀怪（2026-10-26 hunt-enemy 取证已定：4471 的 815 同型）。8824 囚牢在客户端 `map/outergent/04normal1(1,1)`（2 只）、`05normal1(3,3)`（2 只）、`12bonus/13bonus`（各 1 只），服务端 `data/passive-objects-FG360.dat` 已完整登记（10053/10054/10061/10062）。
2. **客户端从不上报物件破坏帧**：原生链路是客户端发 op42（die 帧）带 passiveFlag=1 → 服务端 `CParty::DestroyPassiveObject`。本客户端**全部归档会话 0 条真实上报**（唯一 3 条 PASSIVE_OBJECT_REPORT 是 10-28 晚 FG375 合成路径自己写的日志，d110 书架）。FG375 的兜底＝房间打完/离开时，按房图声明的物件数合成记账——但当时**只对带 `[destroy object]` 清条件的副本生效**（`HasClearConditionFG372` 门禁）。根特外围清条件是杀 boss，不满足 ⇒ 4203 的计数永远无人喂。
3. **旁证**：10-29 03:14 玩家实机接 4203 进 d80，全程无 op35 触发、无 op42 passiveFlag，只有普通怪击杀（日志 `archive/20261029-031554`）。

## 修复设计（`Batch-Service-FG.cs` 一处，~15 行）

- `CreditRoomDestroyObjectsFG375` 的门禁从"仅 `[destroy object]` 清条件"放宽为"清条件 **或** 当前激活任务存在 `[hunt enemy]` 目标行"；逐物件判定新增 `HuntObjectObjectiveWantsFG383(id)`：行 stride=5、副本列匹配、难度阈值 `Meets`、怪物列==物件 id、**enemyType 列==3**。
- **enemyType==3 过滤是承重的**：物件 id 空间与怪/APC id 重叠（4290 猎 d89 boss APC 10409，而 10409 同时是某图物件号），不过滤会拿无关房间的物件给 APC 猎杀任务误记账。
- 记账仍走原 `PassiveObjectKillFG360` 全链：`DestroyPassiveObjectFG360` 按房图声明数封顶（同房两只囚牢=2 次）、receipt 按 run+房间+序号幂等、`KillWithAssetsFG171` 由引擎再次校验副本/难度/目标上限、`SendQuestWireDeltaFG` 推 op35 进度回包刷新客户端计数显示。无经验、无掉落，与原生语义一致。
- 时机保持 FG375 形态：房间清完（`room-clear`）或 op48 移出（`move`）时结算。
