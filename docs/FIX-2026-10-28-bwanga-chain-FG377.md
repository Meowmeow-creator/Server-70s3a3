### 1.3 选块与客户端表现（rednf 对照）

- `rednf BattleDepsB2/GetAppropriateMaze.inc`：questType 0 走 `CheckQuestConnection` =
  `IsDoingQuest(questIdx)`，且 type 0 额外要求 `m_questMinDiff <= diff`；
  候选 1 个直取、多个 `rand()%n`；**无候选回退 `GetRandMazebyPartyCount`（base 块）**。
- 客户端不自己按任务选块：op28 第 3 字节 = `m_mazeType`（块序号），客户端拿它索引自己
  `.dgn` 的 `[maze info]` 块建房间格网（FG374 dump 实证 `0x47A530: rowBase[page]*Y+X`），
  再按收到的房间包逐格点亮/进入。**"全图" = 当前块就是 10 格 base**；
  "慢慢开图" = 考验链让块依次变成 2→4→6→8→9→10 格，最后到布万加。
- 服务端与客户端因此永远看同一个块；单机默认宽容难度（`DNF70_QUEST_DIFFICULTY_STRICT`
  未开时 MinDiff 只作参考），与 FG365 的单机策略一致。

### 1.4 精英怪（champion）不是 bug

base 块房间里随机把一只普通怪升成精英是 native 的 `[champion]` 表 + `getAddChampionMobCnt`
机制（d141 表 = 6/12/18/24/26，按难度缩放；命名怪 56000..60000 不参与）。
该机制由 `Elite-Monsters-FG118.cs` 完整实现：base 局每房固定掷出一只 elite。
四只命名精英在 base 局保持普通（PVF 就是 `[normal]`），它们变 BOSS 的唯一途径是阶段块。

## 4. 给玩家的说明（可直出）

- 修炼场是"考验链"副本：在万年雪山找**奥尔卡**依次接【鹰眼的考验→马尔加的考验→
  拉里的考验→美杜莎莎的考验→雀瑟的考验→英雄的考验】。
- 接哪个考验，进图就是那一阶段的走廊：2 间（霍克伊）→4 间（冰王马拉加）→6 间
  （莱里特·拉里）→8 间（美杜莎莎）→9 间（雀瑟）→10 间（布万加）。这就是"慢慢开图"。
- 没有接任何考验时，副本是完整 10 间、终点布万加（原版行为）；地图一次显示整条走廊
  是客户端小地图的固定画法（所有副本一致），不是服务端"全开"。
- 四只精英在短阶段里才以 BOSS 身份出场；普通/收尾局里它们是默认形态，
  房间里随机出现的精英（金色名）是另一套机制，属正常。
