## 1. `[quest connection]` 迷宫：26 个副本，只加载了 9 个

`Forest-Content-FG75.Map()` 逐格对比（这一项同时是回归检查：base 块不一致就意味着普通刷图的
迷宫会变）。

| 情况 | 副本 | 结论 |
|---|---|---|
| 已在 FG361 表里且 base 与 Forest 一致 | 45、83、84、85、89（+ 60/61/81 是"修好后不一致"） | 正常 |
| **base 块本身就是任务迷宫**（Forest 一直按 quest 布局刷普通图） | **82**、140；60/61/81（批次一已修） | d82 本轮已补；d140 属 Act4，留给 Act4 那条线 |
| base 与 Forest 完全一致、但任务迷宫从未加载 | **25、52、53、87、92、93、110、1501** | 本轮全部加入 |

**56502 / 61710 / 56503**——正好是 3249 卡勒特干部徽章剩下三个军官。补上后 11/11 个军官全部可刷
（验收里逐个跑过 40 次王者击杀）。

## 3. 两个"没源"的类别

### 3a. 怪物专属掉落被清空（42 只）

`monster/*.mob` 明明写着 `[item]` / `[common champion drop item]` 等，`Floor-Catalog-FG119` 里却是
`p.Add(id,{ {},{},{},{} })` —— **打死了不掉任何东西**。全库 494 个有名册的怪，446 只完全一致，
**42 只全空**：

- 死亡之塔整套 55001–55025、幻影塔 50501–50509、极限之塔 56438–56445（塔内怪物＝零掉落）；
- Act4 幼龙 60030、根特两个 BOSS 61112 / 61710。

工具 `apply_monster_pools_fg360.py` 只填"四列全空且 PVF 有行"的怪；三个手调过的（1078/1096 的
3171 权重 9000、56713 多出的 3227 行）**原样保留**；纯 3227 的（服务端延迟到副材料页）跳过。
另有 61111 的 `[item] 3227 800` 属同一类但被 3227 规则排除，记录在案。
**注意：重跑 `gen_monster_pools.py` 会覆盖这 42 条，需要再跑一次本工具。**

### 3b. `[seeking]` 目标物品无源

51 → 37 个 id（补物件掉落后减少 11 个）。剩下 37 个在所有已实现系统里都没有出处：

- **物件掉落连任务房都没覆盖**：`gen_object_drops.py` 自己带一份 36 个副本的 `DIRNAME` 副本，
  所以 Act5+/根特/Act7（50-53、60/61、80-93、110-112、140、1500+、3503）**根本没有物件掉落**；
  就算有池，任务迷宫房间也不在"可达房间"集合里（16337 的 `[special passive object] 8944` 因此
  永远不掷 3269 柴火）。本轮把副本表统一到 `gen_dungeon_content.DIRNAME`（单一来源）并把
  FG361/FG362 的房间并入可达集合：**96 → 356 张带动作的房间、34 → 57 个池物品**
  （复现闸门 96/96 全过，bounds 全过）。
- 补齐后仍无源的 37 个，逐类判定：
  - 分解主产物类（3031 银锭、3062 煤尘、3134 粗糙的布片、3154 上级硬化剂、3159/3160 砥石、
    3262/3263 金色小晶块/大晶体）——原版来自**分解装备的主产物**，我们的分解只实现稀有度 Extras；
  - NPC 商店类（3162/3163 辛达的券、3206/3207 博肯/土罐人偶）——目录里没有对应 NPC 的 offer；
  - 事件/海产类（7248 奇怪的章鱼、7249 鲨鱼、2610013–2610028 海产、4328 挑战书、7401–7403）；
  - 少量任务专属（3315 马萨乔的记录胶囊、3064 十夫长的标记、3067/3068/3070/3074 老地图材料）——
    其 `.mob` 掉落者不在 `monster.lst`，需要原版的 `[special passive object]` 机制扩展。
  **本轮不编造掉率**；这些属于"分解主产物 / 商店覆盖 / 事件系统"，各自要单独立项。

## 6. 补充：塔内掉落改回塔专属（2026-10-27 玩家二次反馈）

玩家反馈"塔内怪物掉的东西错误了，塔内只会掉一些专属的【塔】无色小晶块之类的道具"。
普查第 2 项给 42 只空池怪补 `.mob` 掉落时，把塔的 40 只怪（505xx/550xx/564xx）也补上了，
于是塔里开始掉 1000/1047/1004/3171 这些普通材料 —— **错**。

证据：塔怪的 `.mob` 有两张掉落表：

```
[item] / [common champion drop item]   -> 普通（塔外）掉落
[death tower item]                     -> 塔内掉落
```

`towerofdeath.dgn` / `towerofillusion.dgn` 只有 `[tower fp cubepiece]`、`[tower limit of
stackable item]`、`[tower max clear item num]`，`etc/deathtower.etc` 只有概率/权重
（`[reward item prob] 50 49 100`、`[reward gold weight]`、每层 `[reward exp weight]`、
`[reward card num]`），**物品 id 全在怪物的 `[death tower item]` 里**：

| 怪 | `[death tower item]` |
|---|---|
| 55012 塔明神 / 55016 / 55021 / 55023 | 6515 `(塔)无色小晶块` 10000（必掉） |
| 55024 塔BOSS之父 | 6518 `(塔)迅捷药剂` 10000 |
| 55007 | 6519 `(塔)圣护药剂` 10000 |
| 55022 | 6523 `(塔)上级魔力药剂` 10000 |
| 55005 / 50504 / 50508 | 6515 2000（20%） |
| 50502 / 50507 | 6515 10000 + 6518 10000 |
| 55001 塔哥布林 等 20 只 | 空（不掉） |

落地：
- `data/death-tower-items-FG364.dat`（`gen_death_tower_items_fg364.py`，17 怪 19 行）+
  `Tower-Drops-FG364.cs`：塔里**只**按这张表掷一次累积权重（10000 制，与普通池同口径），
  **不掉金币、不掉装备、不掷通用堆叠/世界掉落/independent**。
- `Floor-Drops-FG119.Plan` 在 `dungeon.TowerFlowFG211` 时直接走这张表并返回。
- `revert_tower_pools_fg364.py` 把 40 只塔怪的普通池清回空（只动"与 PVF 完全一致"的行，手调不动）；
  `apply_monster_pools_fg360.py` 加了塔名单跳过，**以后重跑不会再填回去**。
- 塔物品 6515/6518/6519/6523 出现在掉落表里但没登记，已按 `.stk` 证据补：
  6515 `[material]`→Kind 2，6518/6519/6523 `[waste]`→Kind 1（与 1137/1234 同口径）。
- 验收：driver 增加 G 段——17 条塔表加载、55012/55024 必掉对应道具、55001 不掉、
  55005 的 2000 权重≈20%、**45 层死亡之塔逐层扫一遍只有 death-tower 行**、非塔怪填充保留。

另外：`scripts/check_repo.py` 有一份"稳定源禁止塔实现"的前缀名单（`Death-Tower*` 等）。
